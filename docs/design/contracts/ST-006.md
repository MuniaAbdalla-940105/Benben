**The one ledger model** used by ST-007 (payments), ST-008 (join locks) and every later money story. Nothing outside `private.ledger_post()` writes ledger rows or wallet balances.

## 1. Tables

### 1.1 `public.wallets`
| Column | Type | Constraints |
|---|---|---|
| `id` | `uuid` | `pk default gen_random_uuid()` |
| `user_id` | `uuid` | `not null references profiles(id) on delete restrict` |
| `currency` | `char(3)` | `not null default 'EGP' check (currency = 'EGP')` |
| `available` | `bigint` | `not null default 0 check (available >= 0)` |
| `locked` | `bigint` | `not null default 0 check (locked >= 0)` |
| `pending` | `bigint` | `not null default 0 check (pending >= 0)` |
| `forfeited` | `bigint` | `not null default 0 check (forfeited >= 0)` (lifetime total of forfeits; display bucket, PRD 2.3) |
| `status` | `text` | `not null default 'active' check (status in ('active','frozen'))` |
| `version` | `bigint` | `not null default 0` (+1 per posting; lets the UI detect stale reads) |
| `created_at` / `updated_at` | `timestamptz` | `not null default now()` |

Constraints: `unique (user_id, currency)`, which gives exactly one EGP wallet per user (AC).
Trigger `private.guard_wallet_balances()` `BEFORE UPDATE`: if any of `available, locked, pending, forfeited, version` changes and `current_setting('benben.ledger_posting', true) is distinct from 'on'`, it raises `P0001 'DIRECT_BALANCE_EDIT_FORBIDDEN'`. Only `ledger_post()` sets the flag, transaction-local.

### 1.2 `public.ledger_accounts`
| Column | Type | Constraints |
|---|---|---|
| `id` | `uuid` | pk |

| `currency` | `char(3)` | `not null default 'EGP'` |

Constraints:
- `check ((kind::text like 'user_%') = (wallet_id is not null))`;
- `check ((wallet_id is null) = (code is not null))`;
- `unique (wallet_id, kind)`.

Normal sides: `user_available`, `user_locked`, `user_pending`, `revenue_forfeit`, `revenue_premium` and `refunds_payable` are **credit**. `gateway_clearing`, `pending_clearing` and `test_funding` are **debit**.

Seeded system accounts:
- `gateway_clearing:paymob`, `gateway_clearing:mock`;
- `pending_clearing:paymob`, `pending_clearing:mock`;
- `revenue_forfeit`, `revenue_premium`, `refunds_payable`;
- `test_funding` (created in every env; `private.dev_fund_wallet` refuses to run in production).

### 1.4 `public.ledger_entries` (append-only)
| Column | Type | Constraints |
|---|---|---|
| `id` | `bigint` | `generated always as identity primary key` |
| `txn_id` | `uuid` | `not null references ledger_transactions(id)` |
| `account_id` | `uuid` | `not null references ledger_accounts(id)` |
| `wallet_id` | `uuid` | copied from the account (null for system accounts); used by owner RLS |
| `debit` | `bigint` | `not null default 0 check (debit >= 0)` |
| `credit` | `bigint` | `not null default 0 check (credit >= 0)` |
| `currency` | `char(3)` | `not null default 'EGP' check (currency = 'EGP')` |
| `created_at` | `timestamptz` | `not null default clock_timestamp()` |

Constraints and triggers:
- `check ((debit > 0) <> (credit > 0))`: exactly one side per line.
- `private.check_txn_balanced()`: `CONSTRAINT TRIGGER … AFTER INSERT … DEFERRABLE INITIALLY DEFERRED FOR EACH ROW`. At commit it asserts `sum(debit) = sum(credit)`, `count(*) >= 2`, and a single currency for `txn_id`. Otherwise it raises `P0001 'LEDGER_IMBALANCE'`.

Indexes: `(txn_id)`, `(account_id, id)`, `(wallet_id, id desc)`.

### 1.5 `public.wallet_locks`
| Column | Type | Constraints |
|---|---|---|
| `id` | `uuid` | pk |
| `wallet_id` | `uuid` | `not null references wallets(id)` |
| `user_id` | `uuid` | `not null references profiles(id)` (denormalised for RLS) |
| `purpose` | `lock_purpose` | `not null` (`auction`, `seller_commitment` (Q-13), `rental_deposit`) |
| `ref_type` | `text` | `not null` (e.g. `auction`) |
| `ref_id` | `uuid` | `not null` |
| `amount` | `bigint` | `not null check (amount > 0)` |
| `currency` | `char(3)` | `not null default 'EGP'` |
| `status` | `lock_status` | `not null default 'active'` |
| `lock_txn_id` | `uuid` | `not null references ledger_transactions(id)` |
| `close_txn_id` | `uuid` | `references ledger_transactions(id)` |

| `created_at` | `timestamptz` | `not null default clock_timestamp()` |
| `closed_at` | `timestamptz` | |

Constraints and indexes:
- `unique (wallet_id, purpose, ref_type, ref_id) where status in ('active','frozen')`: **one live lock per purpose and reference**, so a double join cannot double-lock (ST-008 AC).
- `check ((status in ('active','frozen')) = (close_txn_id is null))`.
- Indexes: `(ref_type, ref_id, status)` (auction close releases), `(user_id, created_at desc)`.

## 2. Movements (the only ways money moves)

All movements go through `private.ledger_post()`. Keys are deterministic, so retries are safe.

| Function (private) | Txn type | Lines (D = debit, C = credit) | Lock change | Idempotency key |
|---|---|---|---|---|
| `wallet_credit_capture(user, amount, payment_id, gateway)` | `payment_capture` | D `gateway_clearing:<gw>` / C `user_available` | — | `payment:<payment_id>:capture` |
| `wallet_pending_add(user, amount, payment_id, gateway)` | `payment_pending` | D `pending_clearing:<gw>` / C `user_pending` | — | `payment:<payment_id>:pending` |
| `wallet_pending_reverse(user, amount, payment_id, gateway)` | `payment_pending_reversal` | D `user_pending` / C `pending_clearing:<gw>` | — | `payment:<payment_id>:pending_reversal` |
| `wallet_duplicate_capture(amount, payment_id, gateway, user)` | `duplicate_capture` | D `gateway_clearing:<gw>` / C `refunds_payable` | — | `payment:<payment_id>:duplicate` |
| `wallet_lock(user, amount, purpose, ref_type, ref_id, key)` | `lock` | D `user_available` / C `user_locked` | new `active` lock | `lock:<key>` |
| `wallet_release(lock_id, reason, key)` | `release` | D `user_locked` / C `user_available` | → `released` | `release:<lock_id>` |
| `wallet_forfeit(lock_id, reason, key)` | `forfeit` | D `user_locked` / C `revenue_forfeit`, and `wallets.forfeited += amount` | → `forfeited` | `forfeit:<lock_id>` |
| `wallet_apply(lock_id, charge_ref_type, charge_ref_id, key)` | `apply` | D `user_locked` / C `revenue_premium` | → `applied` | `apply:<lock_id>` |
| `dev_fund_wallet(user, amount, key)` (non-prod) | `test_funding` | D `test_funding` / C `user_available` | — | `devfund:<key>` |

Release, forfeit and apply use the lock id as their key, so a lock can be closed **once**. A second close returns the first result (`replayed`).

## 3. Functions

All functions are in `private`, `SECURITY DEFINER`, `SET search_path = ''`, and **not executable by `anon`/`authenticated`**. Clients reach them only through the public RPCs of ST-008 (`join_auction`, `leave_auction`) and the ST-007 Edge Functions.

### 3.1 `private.ledger_post(...) returns uuid`
```
ledger_post(
  p_type ledger_txn_type,
  p_idempotency_key text,
  p_lines private.ledger_line[],       -- composite (account_id uuid, debit bigint, credit bigint)
  p_wallet_id uuid, p_ref_type text, p_ref_id uuid,
  p_payment_id uuid, p_lock_id uuid, p_memo text,
  p_actor_type actor_type, p_actor_id uuid
) returns uuid  -- txn id
```
1. Compute `params_hash`. If `idempotency_key` exists: the same hash returns the existing txn id; a different hash raises `P0001 'DUPLICATE_REQUEST'`.
2. Validate: at least 2 lines, each with exactly one side > 0, Σdebit = Σcredit, all accounts EGP. Otherwise raise `LEDGER_IMBALANCE`.
3. `SELECT … FROM wallets WHERE id = ANY(<wallet ids of the user accounts in the lines>) ORDER BY id FOR UPDATE`.
4. `set_config('benben.ledger_posting','on', true)`, then insert the txn and the entries, then update the cached buckets on each affected wallet. For credit-normal user accounts, `bucket += credit − debit`, and `version += 1`. A `CHECK (>= 0)` violation becomes `P0001 'INSUFFICIENT_BALANCE'`. Finally `set_config('benben.ledger_posting','off', true)`.
5. Return the txn id.

It **raises** on failure; it is internal. The wrapper functions below catch the exception and return the envelope.

### 3.2 Wrapper result type
```sql
create type private.wallet_op_result as (
  ok boolean, error_code text, replayed boolean,
  txn_id uuid, lock_id uuid,
  available bigint, locked bigint, pending bigint
);
```

### 3.3 `private.wallet_lock(p_user_id uuid, p_amount bigint, p_purpose lock_purpose, p_ref_type text, p_ref_id uuid, p_key text) returns private.wallet_op_result`
1. Look up the wallet. If none → `NOT_FOUND`. If `status = 'frozen'` → `WALLET_FROZEN`.
2. Replay: if a txn with key `lock:<p_key>` exists, return it (`replayed = true`).
3. `SELECT … FOR UPDATE` the wallet row. This is the **per-wallet serialization** for concurrent locks (AC).
4. If an active lock exists with the same `(purpose, ref_type, ref_id)` → return it (`replayed = true`, no new lock).
5. If `available < p_amount` → `INSUFFICIENT_BALANCE` with `available`. Nothing is written.
6. `ledger_post(lock)`, then insert `wallet_locks` (status `active`, `lock_txn_id`).

Errors: `NOT_FOUND`, `WALLET_FROZEN`, `INSUFFICIENT_BALANCE`, `INVALID_AMOUNT` (≤ 0), `DUPLICATE_REQUEST`.

### 3.4 `private.wallet_release | wallet_forfeit | wallet_apply (p_lock_id uuid, p_reason text, …) returns private.wallet_op_result`
1. `SELECT … FROM wallet_locks WHERE id = p_lock_id FOR UPDATE`, after locking the wallet row first (lock order: wallets → wallet_locks).
2. If status is already the target, it is a replay. If status is not `active` → `LOCK_NOT_ACTIVE` with `status`.
3. Post the movement and set `status`, `close_txn_id`, `close_reason` and `closed_at`.

### 3.5 Checks used by tests and later reconciliation
| Function | Returns |
|---|---|
| `private.wallet_reconcile(p_wallet_id uuid)` | `table(bucket text, cached bigint, ledger bigint, ok boolean)` for `available`, `locked`, `pending`, `forfeited`, plus a `locks_vs_locked` row (Σ active and frozen lock amounts = cached `locked`) |
| `private.ledger_trial_balance()` | `table(total_debit bigint, total_credit bigint, ok boolean)` over all entries |
| `public.staff_wallet_reconcile(p_wallet_id uuid)` | Same as `wallet_reconcile`, executable by authenticated, returns `FORBIDDEN` unless `finance.read` (used by ST-043 later) |

### 3.6 User creation
`private.create_wallet_for(p_user_id uuid) returns uuid` creates the wallet and its 3 user accounts. It is idempotent. ST-006's migration redefines `private.handle_new_user()` to call it after inserting the profile, and backfills wallets for existing users.

## 4. RLS policies

**Plain words:**

| Table | anon | authenticated (owner) | staff | functions |
|---|---|---|---|---|
| `wallets` | none | SELECT own wallet | SELECT all with `finance.read` | write via `ledger_post` only |
| `ledger_accounts` | none | SELECT own wallet's accounts | SELECT all with `finance.read` | write via migrations/functions |
| `ledger_transactions` | none | SELECT where `wallet_id` = own wallet | SELECT all with `finance.read` | INSERT via `ledger_post` only |
| `ledger_entries` | none | SELECT where `wallet_id` = own wallet (own lines only; system counter-lines are hidden) | SELECT all with `finance.read` | INSERT via `ledger_post` only |
| `wallet_locks` | none | SELECT own (`user_id = auth.uid()`) | SELECT all with `finance.read` or `auction.read` | write via wallet functions only |

**No client INSERT/UPDATE/DELETE grant on any of these tables** (AC: "RLS denies it").

```sql
-- pattern repeated for each table
alter table public.wallets enable row level security;
revoke all on public.wallets from anon, authenticated;
grant select on public.wallets to authenticated;
create policy wallets_owner_select on public.wallets
  for select to authenticated using (user_id = (select auth.uid()));
create policy wallets_finance_select on public.wallets
  for select to authenticated using ((select private.has_permission('finance.read')));

create policy ledger_transactions_owner_select on public.ledger_transactions
  for select to authenticated
  using (wallet_id in (select w.id from public.wallets w where w.user_id = (select auth.uid())));
create policy ledger_entries_owner_select on public.ledger_entries
  for select to authenticated
  using (wallet_id in (select w.id from public.wallets w where w.user_id = (select auth.uid())));
create policy ledger_accounts_owner_select on public.ledger_accounts
  for select to authenticated
  using (wallet_id in (select w.id from public.wallets w where w.user_id = (select auth.uid())));
create policy wallet_locks_owner_select on public.wallet_locks
  for select to authenticated using (user_id = (select auth.uid()));
-- + *_finance_select policies with private.has_permission('finance.read')

create trigger ledger_transactions_append_only before update or delete on public.ledger_transactions
  for each row execute function private.forbid_mutation();
create trigger ledger_entries_append_only before update or delete on public.ledger_entries
  for each row execute function private.forbid_mutation();
create trigger wallets_guard before update on public.wallets
  for each row execute function private.guard_wallet_balances();
create trigger wallets_no_delete before delete on public.wallets
  for each row execute function private.forbid_mutation();
```

## 7. Backend tests

pgTAP (`supabase/tests/st006_*.test.sql`):
1. A new auth user gets exactly **one** wallet, all buckets at 0, and 3 user accounts (`user_available`, `user_locked`, `user_pending`).
2. Zero-sum: after each movement type, `ledger_trial_balance().ok` is true, and each txn has Σdebit = Σcredit.
3. Inserting an unbalanced txn directly (service role, bypassing `ledger_post`) fails at commit with `LEDGER_IMBALANCE`.
4. Negative refusal: wallet with 3,000 EGP available; `wallet_lock(5,000)` → `INSUFFICIENT_BALANCE`, and nothing changes (balances, locks and txn count are the same as before).
5. Idempotency: `wallet_lock` twice with the same key → one txn, one lock, second call `replayed = true`. `ledger_post` with the same key and different lines → `DUPLICATE_REQUEST`.
6. Release, forfeit and apply move the right buckets. `forfeit` raises `wallets.forfeited`. A second release of the same lock → replay. Release after forfeit → `LOCK_NOT_ACTIVE`.
7. Two active locks for the same `(purpose, ref)` are impossible (the unique index rejects a raw insert).
8. Direct edits: as `authenticated`, `insert into wallets / ledger_entries / ledger_transactions / wallet_locks` → permission denied; `update wallets set available = 1` → permission denied. As service role without the posting flag, `update wallets set available = 1` → `DIRECT_BALANCE_EDIT_FORBIDDEN`. `delete from ledger_entries` → `APPEND_ONLY`.
9. `wallet_reconcile()` shows `ok = true` for every bucket after a scripted sequence (fund 20,000 → lock 5,000 → lock 5,000 (second auction) → release 5,000 → forfeit 5,000).
10. RLS: user A sees only A's wallet, locks, transactions and entries. A selecting B's wallet id returns 0 rows. A cannot see system account lines.
11. `dev_fund_wallet` with `runtime_env = production` → `NOT_ALLOWED_IN_ENV`.

Concurrency (`supabase/tests/concurrency/st006_lock_race.test.ts`, Node + `pg` with 2–20 parallel connections, run in CI after `db reset`):
12. Wallet with 7,000 EGP available; two parallel `wallet_lock(5,000)` calls for different auctions → exactly one succeeds and the other returns `INSUFFICIENT_BALANCE`. Final `locked = 5,000`, `available = 2,000`, and reconcile is ok.
13. 20 parallel locks of 1,000 EGP on a 10,000 EGP wallet → exactly 10 succeed and the balance never goes negative.
