# Data contract ST-009: auction detail for guests — catalog, auctions, read side, server time and seed

- Story: `backlog/stories/ST-009.md` · Owner: react-frontend · Helpers: supabase-backend (builds this schema), ui-ux-designer
- Architecture: `docs/decisions/ADR-002-architecture.md` §5 (increments), §6 (time sync, channels), §10 (public projections), §12 (reserve) · Conventions, enums and errors: `DATA_MODEL.md`
- PRD: 3.2 (states), 3.6 (server-time countdown), 3.10 (`properties`, `auctions`, `auction_events`), 8.6 (properties as the hub)
- Assumptions: Q-19 (full state list), Q-22 (no reserve indicator), Q-32 (bidder count = active participants), Q-74 (synthetic areas)
- Migration: `<ts>_st009_catalog_auctions.sql` (fourth). **Placement note:** this migration also creates `bids` and the view `bid_public` exactly as specified in `ST-010.md` §1. That lets the guest page and the seed show bid history before ST-010 ships `place_bid`. ST-010 owns their specification and tests. `auction_participants` is created later (ST-008, sixth migration), so two foreign keys are added by the **ST-008** migration and not here: `bids.participant_id → auction_participants(id)` and `auctions.current_leader_participant_id → auction_participants(id)`.

### 1.5 `public.increment_tables` and `public.increment_bands` (logic in ST-010)
| Table | Columns |
|---|---|
| `increment_tables` | `id uuid pk`, `code text unique not null`, `name text not null`, `currency char(3) default 'EGP'`, `in_use boolean not null default false` (set when an auction references it; once `true`, bands are immutable), `created_at` |
| `increment_bands` | `table_id uuid references increment_tables`, `from_amount bigint not null check (from_amount >= 0)`, `increment bigint not null check (increment > 0 and increment % 100 = 0)`, `primary key (table_id, from_amount)` |

Trigger: insert, update or delete on bands of a table with `in_use = true` raises `P0001 'INCREMENT_TABLE_IN_USE'`. Every table must have a band at `from_amount = 0`; this is checked when an auction is assigned.

Seed `default_v1` (PRD 3.5, piasters):

| `from_amount` | `increment` | Meaning |
|---|---|---|
| `0` | `1000000` | < EGP 1,000,000 → EGP 10,000 |
| `100000000` | `2500000` | EGP 1M–4,999,999 → EGP 25,000 |
| `500000000` | `5000000` | EGP 5M–9,999,999 → EGP 50,000 |
| `1000000000` | `10000000` | ≥ EGP 10M → EGP 100,000 |

## 2. Public projections (clients read these; base-table columns are granted only as needed)

```sql
-- property_public
create view public.property_public with (security_invoker = on) as
select p.id, p.type, p.area_id, p.compound_id, p.title_ar, p.title_en, p.description_ar, p.description_en,
       p.size_m2, p.bedrooms, p.bathrooms, p.floor, p.finishing, p.delivery_status, p.delivery_date,
       p.payment_plan_json, p.verified_status
from public.properties p;

-- auction_public
create view public.auction_public with (security_invoker = on) as
select a.id, a.property_id, a.public_status as status, a.start_at, a.ends_at, a.original_ends_at,
       a.starting_price, a.current_price,
       public.auction_min_next_bid(a.increment_table_id, a.starting_price, a.current_price, a.bid_count) as min_next_bid,
       public.increment_for(a.increment_table_id, coalesce(a.current_price, a.starting_price)) as current_increment,
       a.current_leader_participant_id, a.current_leader_alias_number, a.bid_count, a.bid_seq,
       a.participant_count, a.deposit_amount, a.buyer_premium_bps, a.down_payment_bps,
       a.extensions_count, a.max_extensions, a.payment_terms_ar, a.payment_terms_en,
       a.handover_date, a.currency, a.updated_at
from public.auctions a
where a.public_status <> 'hidden';
```
`public.auction_min_next_bid` and `public.increment_for` are `STABLE` SQL functions, `EXECUTE` granted to anon and authenticated, and specified in ST-010 §3.1.

## 3. Read RPCs

### 3.1 `public.server_time() returns timestamptz` (anon, authenticated)
`select clock_timestamp()`. `VOLATILE`. Used by the time-sync algorithm (ADR-002 §6; ST-011 §4).

### 3.2 `public.get_auction_live_state(p_auction_id uuid) returns public.auction_live_state` (anon, authenticated)
One call that returns everything the live parts of AU-02 need, plus `server_now`. It is used on first load and on every reconnect (A6).
```sql
create type public.auction_live_state as (
  ok boolean, error_code text,                         -- AUCTION_NOT_FOUND
  auction_id uuid, status auction_public_status,
  starting_price bigint, current_price bigint, min_next_bid bigint, current_increment bigint,
  bid_seq bigint, bid_count int, ends_at timestamptz, extensions_count int,
  current_leader_participant_id uuid, current_leader_alias_number int, participant_count int,
  deposit_amount bigint, buyer_premium_bps int,
  my_participant_id uuid, my_alias_number int, my_participation_status participant_status,  -- null for anon
  i_am_leading boolean,                                -- null for anon
  server_now timestamptz                               -- clock_timestamp() at the end of the read
);
```
`SECURITY DEFINER`, `STABLE`, `search_path = ''`. It reads the caller's own participant row with `auth.uid()`. It never returns `status` (internal), `seller_id` or the reserve.

**Realtime: the auction channel `auction:<uuid>`** (receive-only for clients):
```sql
create policy realtime_auction_channel_receive on realtime.messages
  for select to anon, authenticated
  using (
    realtime.messages.extension = 'broadcast'
    and (select realtime.topic()) ~ '^auction:[0-9a-f-]{36}$'
    and private.auction_is_public(substring((select realtime.topic()) from 9)::uuid)
  );
-- No INSERT policy for anon/authenticated: only server functions (realtime.send) publish.
```
If `anon` cannot join private channels on our plan, follow the fallback in ADR-002 R5 (anonymous sign-in for guests). It is checked on day 1 of ST-012.
