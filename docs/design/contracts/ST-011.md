- Story: `backlog/stories/ST-011.md` · Owner: react-frontend · Helpers: ui-ux-designer, supabase-backend
- Architecture: `docs/decisions/ADR-002-architecture.md` §5, §6 · Conventions, enums and errors: `DATA_MODEL.md`
- Server side: `ST-010.md` (`place_bid`, `auction:<id>` payloads), `ST-009.md` (`auction_public`, `bid_public`, `get_auction_live_state`, `server_time`), `ST-008.md` (participation and `user:<uid>`)
- PRD: 3.4, 3.5 (quick buttons, confirmation sheet, idempotency, no self-outbid), 3.6 (server time), 3.9 **A5, A6**, 3.11 (AU-02, AU-05), 8.3 (outbid haptic)
- Assumption: Q-08 (no VAT line until Finance confirms)

**No new tables.** This contract fixes the RPCs, subscriptions, client state rules and error handling the UI must implement. It also fixes the shared code in `packages/shared` that encodes them, so that web, admin, tests and the load harness behave the same way.

## 1. Data the bid bar needs

| Field | Source | Refreshed by |
|---|---|---|
| `status`, `ends_at`, `starting_price`, `current_price`, `min_next_bid`, `current_increment`, `bid_seq`, `bid_count`, `current_leader_participant_id`, `current_leader_alias_number`, `participant_count`, `buyer_premium_bps` | `rpc('get_auction_live_state', { p_auction_id })` | `bid.placed`, `auction.extended`, `auction.state_changed`, `participants.updated`, the `place_bid` response, and resync |
| `my_participant_id`, `my_alias_number`, `my_participation_status`, `i_am_leading` | same RPC (null for guests) | `user:<uid>` `participation.updated`; recomputed on each `bid.placed` (`leader_participant_id === my_participant_id`) |
| `server offset` | `rpc('server_time')` × 3 (§4) | reconnect, `visibilitychange`, every 5 min, "future" `server_ts` |
| Bid history (last 50) | `from('bid_public').select('seq,bidder_alias_number,amount,server_ts,status').eq('auction_id', id).order('seq',{ascending:false}).limit(50)` | prepend on `bid.placed` (dedupe by `seq`); refetch on resync |

TanStack Query keys: `['auction', id, 'live']`, `['auction', id, 'bids']`, `['server-time']`. Realtime events **patch the cache** (`queryClient.setQueryData`). They never trigger a refetch, except on a gap (§6).

## 2. Subscriptions

```ts
await supabase.realtime.setAuth();     // private channels need the current JWT (anon key JWT for guests)
const ch = supabase.channel(`auction:${auctionId}`, { config: { private: true } })
  .on('broadcast', { event: 'bid.placed' },           ({ payload }) => onBidPlaced(payload as BidPlacedEvent))
  .on('broadcast', { event: 'auction.extended' },     ({ payload }) => onExtended(payload as AuctionExtendedEvent))     // ST-014
  .on('broadcast', { event: 'auction.state_changed' },({ payload }) => onStateChanged(payload as AuctionStateChangedEvent)) // ST-013
  .on('broadcast', { event: 'participants.updated' }, ({ payload }) => onParticipants(payload as ParticipantsUpdatedEvent))
  .subscribe((status) => { if (status === 'SUBSCRIBED') resync(); if (status === 'CHANNEL_ERROR' || status === 'TIMED_OUT') markDegraded(); });

// logged-in users only
const me = supabase.channel(`user:${userId}`, { config: { private: true } })
  .on('broadcast', { event: 'participation.updated' }, …)   // unlock bid controls after join (ST-008)
  .on('broadcast', { event: 'payment.updated' }, …)         // Join & Lock result (ST-007)
  .on('broadcast', { event: 'wallet.updated' }, …)
  .subscribe();
```
- Call `supabase.realtime.setAuth()` again after `onAuthStateChange` (`SIGNED_IN`, `TOKEN_REFRESHED`). Unsubscribe on unmount.
- Payload types are in `packages/shared/realtime/auction.ts` (ST-010 §6). Ignore payloads where `v !== 1`.

## 3. Event handling rules (`packages/shared/realtime/applyAuctionEvent.ts`, pure function with unit tests)

| Event | Rule |
|---|---|
| `bid.placed` | if `seq <= state.bid_seq` → ignore (duplicate or old). If `seq > state.bid_seq + 1` → **gap → resync** (§6). Else apply: `current_price`, `min_next_bid`, `current_increment`, `bid_count`, `bid_seq = seq`, `current_leader_*`, `ends_at`, `extensions_count`; prepend to history |
| `bid.placed` and I was leading and `leader_participant_id !== my_participant_id` | show the **outbid alert**, and call `navigator.vibrate?.(200)` where supported (ADR-001), unless `prefers-reduced-motion` asks for no motion (then the alert is visual only) |
| `auction.extended` | set `ends_at`, `extensions_count`; show the "+3:00 Extended" toast (ST-014) |
| `auction.state_changed` | set `status`, `ends_at` |
| `participants.updated` | set `participant_count` (bidder count, Q-32) |
| any event | if `server_ts > serverNow()`, nudge the offset forward (§4) |

## 4. Server time and countdown (PRD 3.6; ST-009 AC)

`packages/shared/time/serverClock.ts`:
```ts
// sync(): 3 samples, keep the one with the smallest RTT
const t0 = performance.now(); const { data } = await sb.rpc('server_time'); const t1 = performance.now();
const rtt = t1 - t0; const serverMs = Date.parse(data as string);
anchor = { serverMsAtMid: serverMs, perfAtMid: (t0 + t1) / 2, rtt };
// read
export const serverNow = () => anchor.serverMsAtMid + (performance.now() - anchor.perfAtMid);
export const remainingMs = (endsAtIso: string) => Math.max(0, Date.parse(endsAtIso) - serverNow());
```
- `performance.now()` is monotonic, so **changing the device clock does not affect the countdown**. `Date.now()` is not used for any auction logic.
- Re-sync on: Realtime `SUBSCRIBED` after a reconnect, `document.visibilitychange → visible`, every 5 min, and when an event's `server_ts` is ahead of `serverNow()`.
- At `remainingMs = 0` the bar changes to "Auction ended" and the bid buttons are disabled locally. The server still decides: a late bid returns `AUCTION_ENDED`.
- Countdown colours (ST-003): green > 1 h, amber < 1 h, red < 5 min, always with text too.

## 5. Placing a bid

### 5.1 Amounts (`packages/shared/bidding/amounts.ts`, all integer piasters)
```ts
// inc = state.current_increment (band of current price, or of starting price before the first bid)
quickAmounts(state) = state.bid_count === 0
  ? [state.starting_price, state.starting_price + inc, state.starting_price + 4 * inc]   // +1, +2, +5 increments
  : [state.current_price + inc, state.current_price + 2 * inc, state.current_price + 5 * inc];
// custom input: parseEGPInput (ST-002) → piasters; valid if whole EGP and >= state.min_next_bid
buyerPremium(amount, bps) = (amount * bps + 5000) / 10000  // BigInt math, round half up to the piaster
estimatedTotal(amount, bps) = amount + buyerPremium(amount, bps)   // no VAT line (Q-08)
```
`quickAmounts[0]` always equals `min_next_bid` (unit test against the server function's examples in ST-010 §2).

### 5.2 Confirmation sheet (AU-05) and the "skip confirmation" toggle
- The sheet shows the amount, the buyer's premium (`buyer_premium_bps`), the estimated total and Confirm.
- "Skip confirmation" lives in `sessionStorage` only, so it lasts for this session (AC).

### 5.3 Idempotency and the request
```ts
// one key per confirmed bid intent; reused for retries of THAT intent only
const intent = { key: crypto.randomUUID(), amount, expectedSeq: state.bid_seq };
const { data, error } = await sb.rpc('place_bid', {
  p_auction_id: auctionId, p_amount: intent.amount,
  p_idempotency_key: intent.key, p_expected_seq: intent.expectedSeq,
});
```
- The Confirm button goes to `loading` on the first tap and ignores more taps until the response arrives. Even if two requests escape, the shared key makes the server create one bid (AC: "a double tap does not send two bids").
- Network failure or timeout → retry up to 3× with the **same key** (backoff 200/400/800 ms). A response with `replayed = true` is treated as success.
- `error` (PostgREST exception) → `INTERNAL_ERROR`. Business outcomes are in `data.ok` / `data.error_code`.
- On `ok`: apply `data` to the cache as if it were `bid.placed` with `seq = data.seq`. The broadcast that follows is then ignored as a duplicate.

### 5.4 Error codes the UI must handle (from `place_bid`)
| `error_code` | UI behaviour |
|---|---|
| `OUTBID` | toast "Outbid, new minimum is {min_next_bid}"; update `min_next_bid`/`current_price` from the response; refresh the quick buttons; keep the sheet open with the new minimum preselected (A5) |
| `BID_TOO_LOW` | "Minimum bid is {min_next_bid}"; refresh the amounts |
| `BID_TOO_HIGH` | "That is much higher than the minimum. Check the amount." Show `max_allowed`; the user edits |
| `ALREADY_LEADING` | switch the bar to "You are leading" (disabled) |
| `AUCTION_ENDED` | the bar shows "Auction ended"; disable the controls |
| `AUCTION_NOT_LIVE` | "Bidding has not started"; show the start countdown |
| `AUCTION_PAUSED` | "Bidding is paused"; disable until `auction.state_changed` |
| `NOT_PARTICIPANT` | show the "Join to Bid" bar (open AU-04) |
| `RATE_LIMITED` | "Too many attempts. Try again in {s}s"; disable for `retry_after_ms` |
| `BUSY_RETRY` | silent auto-retry with the same key after `retry_after_ms`; after 3 tries → "Busy, please try again" |
| `DUPLICATE_REQUEST` | bug guard: make a new key and ask the user to confirm again |
| `USER_BANNED` / `USER_SUSPENDED` | the blocked-account message with the reason/date; disable bidding |
| `NOT_AUTHENTICATED` / `ANONYMOUS_NOT_ALLOWED` | route to login (ST-004), then return |
| `INVALID_AMOUNT` | inline error on the custom input |
| `AUCTION_NOT_FOUND`, `INTERNAL_ERROR` | the generic error state with retry |

All copy comes from `errors.<CODE>` i18n keys (DATA_MODEL §6), in AR and EN, with digits per ST-002.

### 5.5 Bar states (derived, never stored)
| Condition | Bar |
|---|---|
| guest, or no active participation | "Join to Bid" (ST-008) |
| `status in (upcoming)` and participant | "Starts in …" (disabled) |
| `status in (live, extended)`, participant, `i_am_leading` | "You are leading" (disabled, AC) |
| `status in (live, extended)`, participant, not leading, `remainingMs > 0` | quick buttons + custom amount |
| `status = paused` | "Paused" (disabled) |
| `remainingMs = 0` or `status in (ended, sold, cancelled)` | "Auction ended" |
| channel degraded (§6) | the current bar + a "Reconnecting…" banner; bidding stays enabled (the server decides) |

## 6. Reconnect and resync (A6 basic; full Live Room in ST-017)

`resync()` runs on first subscribe, after every reconnect, on a `seq` gap and on `visibilitychange → visible`:
1. `serverClock.sync()`.
2. `rpc('get_auction_live_state')` → **replace** the live state (the server state rules).
3. Refetch the bid history first page, and merge by `seq`.
4. If the user was leading before and is no longer → show the outbid alert once.

A resync must not run more than once per second (coalesced). The UI never "replays" missed bids as animations; it simply shows the server state.
