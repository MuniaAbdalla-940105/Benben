# Data contract ST-004: phone OTP auth, profiles (T0), roles and the platform foundation

- Story: `backlog/stories/ST-004.md` · Owner: supabase-backend · Helpers: react-frontend, integration, security
- Architecture: `docs/decisions/ADR-002-architecture.md` §10, §11, §13 · Conventions, enums and errors: `DATA_MODEL.md`
- PRD: 2.1, 2.2 (T0), 8.1.4 (admin roles), 8.2 (shared bans, consent, audit), 8.6 (`users`)
- Migration: `supabase/migrations/<ts>_st004_foundation_identity.sql` (+ `migrations-down/…down.sql`). It is the first **story** migration and runs right after the ST-001 baseline `20261103000000_st001_private_schema_and_runtime_env.sql` (DATA_MODEL §5). It must not re-create schema `private` or table `private.runtime_env`.
- Edge Function → database: ADR-007. Edge Functions call `private` functions only through `public.svc_*` wrappers that only `service_role` can execute.

This contract also defines the **foundation** that all later contracts reuse (schema `private` and the table `private.runtime_env` already exist from ST-001): helper functions, the config store, audit logs, rate limits, the runtime-env flag and the `user:<uid>` realtime channel policy.

Phone format: `auth.users.phone` stores E.164 **without** `+` (e.g. `201012345678`). Valid Egyptian mobile: `^20(10|11|12|15)[0-9]{8}$`. The client shows and accepts `01x xxxx xxxx` or `+20…`, normalises Arabic-Indic digits (ST-002) and sends `+20…`.

Created by the ST-001 baseline migration `supabase/migrations/20261103000000_st001_private_schema_and_runtime_env.sql`. ST-004 does **not** create or alter it.

ST-001 sets these grants and this RLS, and ST-004 keeps them:
- RLS on, no policies.
- `revoke all on table private.runtime_env from public, anon, authenticated`.
- `revoke all on schema private from public`. `anon` and `authenticated` have no `USAGE` on `private` until ST-004 grants it (§5).

Who writes the row:
- `supabase/seed.sql` writes `local` (local and CI);
- the staging deploy writes `staging` (`tools/ci/sql/set-runtime-env-staging.sql`);
- production never gets a row, so it reads as `production`.

No migration ever writes the row.

**Added by ST-004:**
- `private.env() returns text`: `STABLE`, `SECURITY DEFINER`, `SET search_path = ''`. It returns `coalesce((select env from private.runtime_env where id), 'production')`, so it fails closed. Dev-only SQL functions start with `if private.env() = 'production' then return NOT_ALLOWED_IN_ENV`. No `EXECUTE` for `public`, `anon` or `authenticated`.
- `public.svc_runtime_env() returns text`: `STABLE`, `SECURITY DEFINER`, `SET search_path = ''`. Its body is `select private.env()`. `EXECUTE` goes to `service_role` only, and the function is not on the RPC allow-list (ADR-007 §3.1).
- Edge Functions learn the environment with `requireNonProduction()` (ADR-007 §3.2). It calls `svc_runtime_env`, and the result must equal the function secret `APP_ENV`.

## 4. Server-side functions and Edge Functions

### 4.1 Edge Function `auth-send-sms` (Auth Send SMS hook)
- **Input** (from Supabase Auth, signed with Standard Webhooks): `{ user: { id, phone }, sms: { otp } }`.
- **Steps:**
  1. Verify the hook signature with `SEND_SMS_HOOK_SECRET`. On failure → 401.
  2. Validate `phone` against the Egyptian mobile regex. On failure → return `{ error: { http_code: 400, message: "INVALID_PHONE" } }`. No SMS is sent.
  3. Apply the per-phone limit: call `private.hit_rate_limit('otp:phone', phone, 5, 3600)` through `private.otp_rate_check(phone)`, which the Edge Function calls via its wrapper `public.svc_otp_rate_check(phone)` (service role only, ADR-007). If it is over the limit → `{ error: { http_code: 429, message: "OTP_RATE_LIMITED" } }`.
  4. Call `SmsSender.send(phone, 'otp', { otp })`. The mock writes to `private.dev_sms_outbox`.
- **Output:** `{}` with HTTP 200 on success. Supabase Auth relays the error message to the client on failure.
- **Errors:** `INVALID_PHONE`, `OTP_RATE_LIMITED`, `INTERNAL_ERROR` (provider failure → 502).

### 4.2 `private.custom_access_token_hook(event jsonb) returns jsonb` (ban gate)
- Reads `profiles.status`, `banned_until` and `ban_reason_code` for `event->>'user_id'`.
- If `status = 'banned'` and (`banned_until` is null or `banned_until > now()`), it returns `{"error": {"http_code": 403, "message": "USER_BANNED:<reason_code>"}}`. No token is issued, and this applies on login and on refresh.
- Otherwise it returns `event` unchanged. **No authorization claims are added** (ADR-002 §10).
- `GRANT EXECUTE … TO supabase_auth_admin`, `REVOKE … FROM authenticated, anon, public`. `supabase_auth_admin` gets `SELECT` on `profiles` through a policy that targets only that role.

### 4.3 Edge Function `dev-sms-inbox` (non-prod only, never deployed to prod)
- The first statement is `requireNonProduction(admin)` (ADR-007 §3.2). If `APP_ENV` and `svc_runtime_env()` do not both say the same non-production environment, the function returns 403 `NOT_ALLOWED_IN_ENV` and reads nothing.
- `GET /dev-sms-inbox?phone=2010…`, header `x-qa-token: $QA_INBOX_TOKEN`. Returns the last 10 rows for that phone. Used by Playwright and QA.

### 4.4 Client calls (no custom RPC needed)
| Action | Call | Errors the UI maps |
|---|---|---|
| Request OTP | `supabase.auth.signInWithOtp({ phone: '+2010…' })` | `INVALID_PHONE`, `OTP_RATE_LIMITED`, Auth `over_sms_send_rate_limit` → `OTP_RATE_LIMITED` |
| Verify OTP | `supabase.auth.verifyOtp({ phone, token, type: 'sms' })` | Auth `otp_expired` → `OTP_EXPIRED`; invalid token → `OTP_INVALID`; `USER_BANNED:<reason>` → `USER_BANNED`; `over_request_rate_limit` → `OTP_RATE_LIMITED` |
| Read own profile | `from('profiles').select('*').eq('id', uid).single()` | |
| Update preferences/name | `from('profiles').update({ name_ar, name_en, locale, digits }).eq('id', uid)` | `42501` if a protected column is sent |
| Logout | `supabase.auth.signOut({ scope: 'local' })` | — (ends the session on this device, AC) |

## 5. RLS policies

**Plain words:**

| Table | anon | authenticated (owner) | staff (permission) | service role / functions |
|---|---|---|---|---|
| `profiles` | none | SELECT own row; UPDATE own row, columns `name_ar, name_en, locale, digits` only | SELECT all with `users.read`; ban changes only through functions (ST-020/047) | all |

| `audit_logs` | none | none | SELECT with `audit.read` | INSERT via `private.audit()` only |
| `staff_*` | none | SELECT own `staff_members` / `staff_member_roles` rows (so the admin can show "my roles") | full read with `users.read` | write (ST-020) |
| `private.*` tables | none (schema not exposed; RLS on, no policies) | none | none | all |

**SQL (specification):**

```sql

revoke all on public.profiles from anon, authenticated;
grant select on public.profiles to authenticated;
grant update (name_ar, name_en, locale, digits) on public.profiles to authenticated;

  for update to authenticated using (id = (select auth.uid())) with check (id = (select auth.uid()));

  for select to anon, authenticated using (is_public);
create policy app_settings_staff_select on public.app_settings
  for select to authenticated using ((select private.has_permission('settings.read')));

alter table public.audit_logs enable row level security;
revoke all on public.audit_logs from anon, authenticated;
grant select on public.audit_logs to authenticated;
create policy audit_logs_staff_select on public.audit_logs
  for select to authenticated using ((select private.has_permission('audit.read')));
```

## 8. Backend tests (pgTAP in `supabase/tests/st004_*.test.sql`, plus Edge Function tests)

RLS and grants:
1. User A `select * from profiles` returns exactly 1 row (A's own). A cannot see B's row (0 rows when filtered by B's id).
2. User A `update profiles set name_en='x' where id = B` → 0 rows affected.
3. User A `update profiles set kyc_tier='T1'` / `roles='{seller}'` / `status='active'` / `banned_until=null` on own row → error `42501`, for each column.
4. anon `select from profiles` → 0 rows / permission denied.
5. anon reads `app_settings` → only `is_public` rows. Authenticated non-staff → same. Staff with aal1 → still only public rows (MFA required).
6. `audit_logs`: authenticated `insert` → denied. Service-role `update`/`delete` → raises `APPEND_ONLY`.
7. Every table in `public` and `private` has `relrowsecurity = true` (shared CI check, `tools/ci/check-rls.sql`).
8. `private.has_permission('users.read')` is false for a staff JWT with `aal = 'aal1'` and true with `aal2`.
