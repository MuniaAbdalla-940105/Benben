## Story
As a KYC Reviewer, I want one queue of T1 exceptions, T2 cases and broker checks with all evidence side by side, so that I can decide quickly and consistently.

## Acceptance criteria
- Given AD-09, when a KYC Reviewer opens it, then cases are sorted by SLA and filterable by type (T1 exception, T2, broker) (PRD F4).
- Given a case, when opened, then it shows ID images, OCR fields, selfie, liveness score and any linked accounts (same ID, phone, device) side by side.
- Given a decision, when the reviewer chooses Approve, Reject (reason required) or Request re-upload (document and reason), then the user's tier/case updates and the user is notified.
- Given a broker case, when approved, then the user gets the Broker role for Marketplace posting only. Assumption (Q-55): manual licence check.
- Given a reviewer, when they try to review their own KYC case, then it is blocked.
- Given any decision, when saved, then it is written to `audit_logs`.
- Given non-KYC roles, when they open AD-09, then access is denied (RLS).
- Given the manual flag action, when a reviewer flags a user for AML/sanctions concerns, then the flag is stored for ST-047. Assumption (Q-07).
