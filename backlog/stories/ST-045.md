## Story
As a Super Admin, I want to change platform rules from one Settings screen with a second approver and full history, so that fees and auction rules can evolve safely without code changes.

## Acceptance criteria
- Given AD-14, when opened, then it lists the configurable rules: deposit amount and tiers, increment tables, anti-sniping window/extension/cap, 48 h window, buyer's premium %, listing fee, seller commitment, strike policy, review SLAs, overlap N, new-account listing limit (PRD 8.1 Configuration). Rentals-only rules are hidden in the MVP.
- Given the seeded configuration used since sprint 1, when this screen ships, then it reads and writes the same config store (no second source of truth).
- Given a change, when a Super Admin saves it, then it becomes pending until a second, different Super Admin approves (PRD 8.1.4). Assumption (Q-70): at least two Super Admins are seeded.
- Given an approved change, when it takes effect, then it applies to new auctions only; existing auctions keep their snapshot values (PRD 8.1.4).
- Given history, when viewed, then every version shows who, when, before/after and reason.
- Given invalid values (e.g., negative deposit, overlapping increment bands), when saved, then validation refuses them.
- Given a VAT line, when configured, then it exists and is off by default. Assumption (Q-08).
