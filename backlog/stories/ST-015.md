## Story
As a Verified Bidder, I want to set a hidden maximum and let the system bid for me, so that I stay on top without watching every second.

## Acceptance criteria
- Given AU-06, when a bidder sets a max, then it must be ≥ current price + 1 increment; the max is never shown to other users.
- Given a new auto-bid and the bidder is not leading, when saved, then the system immediately places the minimum bid needed to lead, up to the max. Assumption (Q-24a).
- Given another bid beats the auto-bidder's position, when it commits, then the system replies in the same serialized transaction with the minimum increment needed, up to the max (PRD 3.5).
- Given two competing auto-bids, when resolved, then the price becomes the lower max + 1 increment (capped at the higher max), and with equal maxima the earlier auto-bid leads (PRD 3.5). Assumption (Q-24b): increment uses the band of the amount being placed.
- Given a manual bid equal to an existing auto-bid max, when processed, then the auto-bid keeps the lead (PRD 3.5).
- Given a manual bid above the auto max, when processed, then the manual bidder leads and the auto-bidder gets an outbid alert. Assumption (Q-24c).
- Given an active auto-bid, when the user raises the max, then it saves without placing a self-outbidding bid; when lowering, the new max must be > current price. Assumption (Q-24d).
- Given one user, when they create a second auto-bid on the same auction, then it replaces the first (one active per user per auction). Assumption (Q-24e).
- Given auto-bid placements, when they happen, then they are bids of type `auto` linked to `auto_bid_id`, count for anti-sniping, and appear in the stream like other bids.
- Given the auction is PAUSED, when other events happen, then no auto-bids are placed. Assumption (Q-24f).
- Given AU-06, when the bidder opens it, then it shows how-it-works text, the current max, edit and cancel.
