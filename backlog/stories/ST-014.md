## Story
As a bidder, I want a last-second bid to extend the auction, so that nobody wins by sniping and everyone has time to respond.

## Acceptance criteria
- Given a valid bid accepted when ≤ 60 seconds remain, when it commits, then `ends_at` becomes bid server time + 3 minutes, the state becomes EXTENDED, `extensions_count` increases by 1, and `auction.extended` with the new `ends_at` is broadcast (PRD 3.6).
- Given a bid accepted with > 60 seconds left, when it commits, then `ends_at` does not change.
- Given an auto-bid reply (ST-015) inside the final 60 s, when it is placed, then it counts as a bid for anti-sniping (PRD 3.5); a manual bid and its instant auto-bid reply in the same transaction cause one extension anchored to the last bid's time. Assumption (Q-25).
- Given no cap (default), when extensions repeat, then there is no limit (PRD 3.6).
- Given a per-auction cap (max extensions or max minutes), when the cap is reached, then later bids are still accepted but do not extend. Assumption (Q-25): whichever comes first, minutes counted from `original_ends_at`.
- Given clients, when `auction.extended` arrives, then the UI shows a "+3:00 Extended" toast and the extension counter, and the countdown uses the new server `ends_at`.
