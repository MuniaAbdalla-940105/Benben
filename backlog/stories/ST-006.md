## Story
As Benben Finance, I want every user's EGP wallet to be built on a double-entry ledger, so that every piaster is traceable and balances can never be edited directly.

## Acceptance criteria
- Given a new user, when their account is created, then exactly one EGP wallet exists with Available, Locked, Pending and Forfeited buckets at 0 (PRD 2.3).
- Given any money movement, when it is recorded, then it is a ledger transaction whose debit and credit entries sum to zero, in integer piasters, with currency EGP.
- Given a client, when it tries to insert, update or delete wallets, ledger entries or locks directly, then RLS denies it; movements happen only through server-side functions.
- Given a lock request, when Available < amount, then it fails with "Insufficient balance" and nothing changes; balances can never go negative (PRD 8.2).
- Given the same idempotency key used twice, when a movement is requested, then only one ledger transaction exists.
- Given lock functions, when called, then they support: lock (Available → Locked, purpose and reference), release (Locked → Available), forfeit (Locked → Benben revenue account), apply (Locked → payment of a charge). Lock purposes include `auction`; `seller_commitment` is added. Assumption (Q-13).
- Given concurrent lock requests on the same wallet, when they race, then the total locked never exceeds Available (row lock per wallet).
- Given cached balances on `wallets`, when compared with the ledger, then they always match (check function used by tests and later by reconciliation).
- Given wallet history, when the owner reads it, then they see only their own entries.
