## Story
As a Super Admin, I want a secure admin dashboard where each staff member sees only their modules and every action is logged, so that operations are controlled and auditable.

## Acceptance criteria
- Given an admin user, when they log in to the admin app, then 2FA (TOTP) is mandatory before any module opens (PRD 8.1).
- Given a non-admin account, when it opens the admin URL, then access is denied.
- Given the roles, when seeded, then they include Super Admin, Ops, Ops Supervisor, Auction Control, Auction Host, KYC Reviewer, Finance, Support, Content Reviewer, Trust & Safety, Post-Auction Agent, Data Entry and Publisher; one person can hold several. Assumption (Q-69).
- Given a role, when the sidebar renders, then only that role's modules from the MVP set appear (AD-01, 02/03, 05, 07, 09, 11, 14, 15, 16/17), each enforced on the server by RLS, not only hidden in the UI.
- Given any admin action, when it writes data, then `audit_logs` records actor, action, entity, before/after JSON, reason and time; audit logs are append-only (PRD 8.1.4, 8.2).
- Given AD-15, when a Super Admin opens it, then they can list admins, assign roles, see 2FA status and search the audit log.
- Given a maker-checker action, when a framework helper is called, then it creates a pending approval that a different admin must approve (used by ST-026, ST-032, ST-042, ST-044, ST-045, ST-047). Self-approval is blocked (C7).
- Given the PRD global search, when this story ships, then it is not included. Assumption (Q-68).
