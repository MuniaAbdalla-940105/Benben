## Story
As a guest, I want to sign up and log in with my phone number and a one-time code, so that I become a Registered User (KYC T0) without remembering a password.

## Acceptance criteria
- Given a guest taps "Join to Bid" or Profile, when they enter an Egyptian mobile number, then a 6-digit OTP is sent through the SMS adapter; on staging the mock adapter delivers it to a test inbox / fixed test numbers. Assumption (Q-40): phone OTP is the only login method.
- Given a correct OTP within its validity, when submitted, then a user record is created (or found) with `kyc_tier = T0` and role Registered User, and the user returns to the screen they came from.
- Given a wrong or expired OTP, when submitted, then a clear error appears and no session is created; after repeated failures OTP requests are rate-limited.
- Given an invalid phone format, when submitted, then the form shows an inline error and no SMS is sent.
- Given a logged-in user, when they log out, then the session ends on that device.
- Given a guest, when they browse auctions, then they can watch, read chat and see masked bid history but cannot bid or chat (PRD 2.1).
- Given the users table, when RLS is tested, then a user can read and update only their own profile fields; `kyc_tier`, `roles`, `status` and `banned_until` cannot be changed by the client.
- Given a banned user (status banned), when they log in, then they are blocked with a reason message (PRD 8.2 shared bans).
