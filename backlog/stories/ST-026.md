## Story
As an Auction Control operator, I want to void a fraudulent or erroneous bid or cancel an auction with a second approver, so that mistakes and fraud are corrected without one person abusing power.

## Acceptance criteria
- Given a bid, when Auction Control requests a void with a reason, then a pending approval is created and nothing changes until an Ops Supervisor approves (PRD 8.1.4).
- Given an approved void, when it executes, then the bid status is `voided` with the reason, the leader and current price are recalculated from remaining valid bids (including auto-bid limits), an event is appended, and all clients get the new state (PRD 3.5).
- Given a cancel request on a live auction, when an Ops Supervisor requests it, then a Super Admin must approve (PRD 8.1.4).
- Given an approved cancel (A16), when it executes, then the auction becomes CANCELLED, all deposit locks are released to Available instantly, and every participant is notified with the reason.
- Given the requester, when they try to approve their own request, then it is blocked.
- Given every step, when it happens, then `audit_logs` stores before/after and reasons.
