## Story
As a frontend engineer, I want the design system tokens and core components in code, so that every screen looks consistent and meets accessibility rules without rework.

## Acceptance criteria
- Given the design system from the ui-ux-designer, when it is implemented, then colour, type, spacing, radius and elevation tokens exist as Tailwind theme values and are the only values used by components.
- Given the sprint 1 screens, when components are built, then at least these exist: button (primary/secondary/destructive, loading, disabled), bottom sheet, badge (incl. red LIVE badge and "Verified Bidder"), countdown, amount display, toast, input (text, phone, OTP, amount), checkbox, card, empty/error/loading states.
- Given the countdown component, when the remaining time crosses thresholds, then it is green > 1 h, amber < 1 h and red < 5 min (PRD 3.11 UX notes), and colour is never the only signal (text or icon too).
- Given RTL, when components render, then they use logical properties (start/end) and mirror correctly; numbers and amounts are not mirrored.
- Given keyboard and screen-reader users, when they use any component, then focus is visible, roles and labels are announced, and contrast meets WCAG 2.2 AA. Assumption (Q-46).
- Given users with reduced-motion settings, when a pulsing timer or toast appears, then motion is reduced.
