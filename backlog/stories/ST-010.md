## Story
As a Verified Bidder, I want my bid to be accepted or rejected fairly by the server and shown to everyone instantly, so that I trust the auction result.

## Acceptance criteria
- Given a bid request, when it reaches the server, then it is processed in a Postgres function that locks the auction row, so bids on one auction are strictly serialized and ordered by server timestamp (PRD 3.5, ADR-001).
- Given a bid, when it is validated, then it is accepted only if: auction is LIVE or EXTENDED and `now() < ends_at`; bidder has an active lock for this auction; amount ≥ current price + minimum increment (or ≥ starting price for the first bid, Assumption Q-20); bidder is not the current leader; bidder is not banned or suspended (PRD 3.5).
- Given the increment, when it is computed, then it comes from the auction's increment table using the band of the current price: < 1M → 10,000; 1M–4,999,999 → 25,000; 5M–9,999,999 → 50,000; ≥ 10M → 100,000 EGP. Assumption (Q-21): any whole EGP amount ≥ the minimum is allowed.
- Given the same idempotency key sent twice (double tap), when processed, then only one bid exists and the second call returns the first result.
- Given two bids at the same millisecond (A5), when processed, then the first wins and the second is rejected with "Outbid, new minimum is X".
- Given an accepted bid, when committed, then `current_price` and `current_leader_id` update, an `auction_events` row (type bid) is appended, and a broadcast with alias, amount, server time and new minimum goes to the auction's realtime channel.
- Given an accepted bid, when timed on staging, then broadcast to subscribers is measured (p95 target < 300 ms, PRD 8.4; full load test is ST-012).
- Given a rejected bid, when returned, then the response has a machine-readable reason and the current minimum.
- Given a bid, when retraction is attempted, then there is no retraction path (PRD 3.5).
- Given RLS, when a client tries to insert into `bids` directly, then it is denied.
- Given bid rate limits, when a user sends bids faster than the configured limit, then extra requests are refused (PRD 8.4).
