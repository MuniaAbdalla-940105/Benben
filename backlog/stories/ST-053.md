## Story
As the stakeholder, I want an independent security audit of the whole MVP before the pilot, so that users' money and identity data are protected.

## Acceptance criteria
- Given every table, when audited, then RLS is enabled and has tests for anon, user, other user and each admin role; any gap is a bug.
- Given money, bid and chat writes, when audited, then none is possible by direct client insert; all go through server functions.
- Given the browser bundle and repo, when scanned, then no service-role key or webhook secret is present.
- Given OWASP ASVS L2, when the checklist is run, then each applicable item is passed or logged as a bug with severity (PRD 8.4).
- Given PII and the reserve price, when checked, then they are encrypted or access-restricted as agreed in the data contracts. Assumption (Q-47).
- Given rate limits on bids, chat, OTP and payments, when tested, then they hold.
- Given dependencies, when scanned, then no known high or critical vulnerabilities remain.
- Given findings, when the audit ends, then a report is linked here and every high finding is fixed or explicitly accepted by the stakeholder.
