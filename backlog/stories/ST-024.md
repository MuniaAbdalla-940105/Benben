## Story
As an Ops agent, I want to check pricing, record the seller agreement and commitment, and schedule the auction, so that only vetted, well-priced auctions go live.

## Acceptance criteria
- Given pricing, when Ops reviews it, then they see starting price, reserve (optional), valuation, deposit tier, increment table, buyer's premium %, down payment %, payment terms and handover date (PRD 3.3, F1 step 5).
- Given reserve > valuation + 15%, when shown, then a warning appears (PRD F1 step 5).
- Given the reserve price, when stored, then it is in a restricted store that clients cannot read; only the seller and Ops can see it through server functions. Assumption (Q-47).
- Given the deposit, when the auction is configured, then it defaults to EGP 5,000 from a configurable tier table based on starting price and is fixed at SCHEDULED. Assumption (Q-12).
- Given the seller agreement and fees, when Ops records them, then the signed Auction Agreement document is stored, the listing fee is recorded as paid, and the seller commitment is held as a wallet lock with purpose `seller_commitment`. Assumption (Q-13): amounts configured by admins.
- Given all checks done, when Ops approves, then the auction is APPROVED (PRD F1 step 6); the approver must be different from the creator (C7).
- Given scheduling, when Ops picks a start time, then it must be ≥ 48 h ahead, and the system blocks more than N auctions ending in the same 30 minutes. Assumption (Q-72): N = 3. On save the auction becomes SCHEDULED.
- Given a SCHEDULED auction, when anyone but Ops edits auction terms, then it is refused (PRD 8.1.5 editing rule).
- Given rejection, when Ops rejects, then the reason is stored and the seller is notified (REJECTED).
- Given scheduling across weekends and holidays, when the 48h winner deadline falls on Fri/Sat, then a warning is shown. Assumption (Q-29).
