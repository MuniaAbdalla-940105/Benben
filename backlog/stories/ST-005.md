## Story
As a Registered User, I want to verify my identity with my National ID and a selfie, so that I can become eligible to bid (KYC T1).

## Acceptance criteria
- Given a T0 user starts KYC, when they upload ID front and back and take a selfie, then the files go to a private storage bucket and are sent to the KYC adapter; on staging a mock adapter returns OCR fields (name, 14-digit National ID, birth date) and a liveness/match score.
- Given the mock returns a pass above the configured score, when the result arrives, then the user is upgraded to `kyc_tier = T1` and sees success. Assumption (Q-36): auto-approve above threshold.
- Given the mock returns a score below threshold or an OCR mismatch, when the result arrives, then the case is marked `needs_review` and the user sees "Under review" (handled by KYC Reviewer in ST-022). Assumption (Q-36).
- Given the mock returns a hard fail, when the result arrives, then the user sees the reason and can retry.
- Given a National ID that fails the 14-digit format check, when submitted, then it is rejected before any vendor call.
- Given a National ID already linked to another account, when submitted, then the case goes to review and is flagged as a possible linked account (PRD A12; Assumption Q-39).
- Given the KYC documents, when RLS is tested, then only the owner (upload) and KYC Reviewer role (read) can access files; no public URLs exist.
- Given the flow, when timed on staging with the mock, then the user path takes under 3 minutes (PRD 3.4 target).
- Given foreign users, when they start KYC, then passport is not offered in the MVP. Assumption (Q-38).
- Given the adapter interface, when the real vendor is chosen later, then it can replace the mock without changing callers (ADR-001).
