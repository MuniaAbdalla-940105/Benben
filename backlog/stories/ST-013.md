## Story
As Benben Auction Control, I want every auction to move through one server-controlled state machine on time, so that no client can start, extend or end an auction early or late.

## Acceptance criteria
- Given the state list in PRD 3.2, when the enum is created, then it contains DRAFT, PENDING_REVIEW, APPROVED, REJECTED, SCHEDULED, LIVE, EXTENDED, PAUSED, ENDED, AWAITING_WINNER, RESERVE_NOT_MET, SELLER_DECISION, NO_BIDS, WINNER_DEFAULTED, SECOND_CHANCE, COMPLETED, CANCELLED, RELISTED, MOVED_TO_MARKETPLACE.
- Given a transition request, when it is not in the allowed transition table, then it is refused and logged. Assumption (Q-19): LIVE/EXTENDED/PAUSED → CANCELLED and EXTENDED → PAUSED are allowed; REJECTED, CANCELLED, RELISTED, MOVED_TO_MARKETPLACE and COMPLETED are terminal.
- Given a SCHEDULED auction, when `start_at` is reached, then a scheduled job (pg_cron + function, ADR-001) sets it LIVE and appends an `auction_events` row (started) and broadcasts it.
- Given a LIVE or EXTENDED auction, when `now() ≥ ends_at`, then bids are refused immediately (lazy check in `place_bid`), and a sweeper job sets ENDED within a few seconds and broadcasts `auction.ended`.
- Given ENDED, when the outcome is computed, then: no valid bids → NO_BIDS; highest bid < reserve → RESERVE_NOT_MET; else → AWAITING_WINNER. Assumption (Q-19): no reserve counts as met.
- Given a SCHEDULED auction, when its start is set, then `start_at` must be at least 48 h ahead (PRD 3.2) and the duration is 24 h. Assumption (Q-33): duration stored per auction, default 24 h.
- Given every transition, when it happens, then an append-only `auction_events` row records type, payload and server time; events can never be updated or deleted.
- Given a client, when it tries to change `status`, `start_at` or `ends_at`, then RLS and column privileges deny it.
