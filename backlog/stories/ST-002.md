## Story
As an Egyptian user, I want the app to open in Arabic (right-to-left) with an English option and readable EGP amounts, so that I can use it comfortably in my own language.

## Acceptance criteria
- Given a first visit, when the app loads, then the UI is Arabic, `dir="rtl"`, and the default tab is **Auctions** in the bottom navigation (Auctions centre and emphasised · Explore · Rent · Requests · Profile/Wallet).
- Given the language switch, when the user picks English, then all shell strings switch to English, layout flips to LTR, and the choice persists across sessions.
- Given the digits toggle, when the user switches between Latin and Arabic-Indic digits, then all numbers, dates and countdowns render in the chosen digits. Assumption (Q-48): Latin digits are the default.
- Given any amount stored as integer piasters, when it is displayed, then it is formatted as EGP with thousands separators and no floating-point maths in the client.
- Given a numeric input, when the user types Arabic-Indic or Latin digits, then both are accepted and normalised. Assumption (Q-48).
- Given dates and times, when they are shown, then they use the Africa/Cairo time zone. Assumption (Q-29).
- Given tabs not in the MVP (Rent, Requests), when the user taps them, then a "Coming soon" state is shown, not an error. Assumption (Q-68, PRD 8.7 phases).
- Given the shell on a 360 px wide phone and a 1280 px desktop, when rendered, then there is no horizontal scroll and touch targets are at least 24×24 CSS px (WCAG 2.2 AA; Assumption Q-46).
