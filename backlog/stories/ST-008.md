## Story
As a KYC T1 user, I want to accept the auction terms and lock my seriousness deposit for one auction, so that I become a Verified Bidder and can bid immediately.

## Acceptance criteria
- Given a guest or T0 user taps "Join to Bid" on AU-02, when they continue, then they are routed through login (ST-004) and KYC T1 (ST-005) first and come back to the Join to Bid sheet (AU-04).
- Given the AU-04 sheet, when it opens, then it shows the deposit explainer, the deposit amount for this auction (default EGP 5,000, from `auctions.deposit_amount`), the user's Available balance, payment methods and a "Lock EGP 5,000" CTA.
- Given the T&C checkbox (deposit, 48h rule, forfeiture, buyer's premium), when it is unticked, then the CTA is disabled; when ticked and confirmed, then acceptance is logged with timestamp, IP, device and T&C version (PRD 3.4, 8.2). Assumption (Q-03): T&C v0 placeholder text on staging.
- Given Available ≥ deposit, when the user confirms, then a lock of the deposit amount is created for this auction, an `auction_participants` row is created with an alias (e.g., "Bidder #7") and status `active`, and the UI shows the "Verified Bidder" badge and unlocks bid controls without a page reload (realtime).
- Given Available < deposit, when the user chooses Join & Lock, then a payment for the missing amount goes through the gateway (ST-007) and becomes a lock for this auction only after the webhook (PRD 2.3 rule 3).
- Given payment declined (A1), when the result arrives, then no lock exists, the reason is shown and nothing unlocks.
- Given a pending payment (A2) confirmed after the auction has ended, when the webhook arrives, then the money goes to Available, not to a lock.
- Given a user already joined this auction, when they tap Join again, then no second lock is created.
- Given a user wants two auctions, when they join a second one, then a second separate lock is required (EGP 10,000 total) (PRD 2.3 rule 2).
- Given the seller of this auction, when they try to join, then it is refused (PRD 2.1). Linked-account checks come in ST-046.
- Given an auction in SCHEDULED, when a user joins, then it is allowed; leaving is possible only before LIVE. Assumption (Q-23).
- Given a suspended or banned user, when they try to join, then it is refused with a reason.
